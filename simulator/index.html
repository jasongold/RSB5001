RSB5001 — Ready Steady Bang

The sketch's state machine, ported line-for-line to the browser so the game can be played without flashing the board. Same constants, same screens, same rules. Press 1–4 to draw, space for the centre button, and A during the bang to make all four stations draw at once — the only way one person can trigger the four-way replay.

Where the simulation differs from the board

  • Timings, screens and rules are taken straight from config.h and the sketch — including the 800–4000 ms steady delay, the 600 ms window held open to rank 2nd–4th, and the 50 ms per-button lockout.
  • Presses register on the leading edge here too, but a keyboard has no contact bounce, so the lockout never has anything to swallow.
  • Timestamps come from performance.now() rather than micros(), and the poll runs once per animation frame instead of once per loop(). Reaction times are therefore quantised to about 16 ms — the board resolves far finer.
  • There is no DFPlayer, so the spoken countdown is silent. On the board that audio command is also the thing that stalls millis() while SoftwareSerial transmits.
  • Writing the screen is free here. On the board every lcdShow() resyncs the controller and repaints all 32 cells — roughly 19 ms, blocking, with no buttonsPoll() running. That cost is why the light show is nearly all LEDs, and why the only screen effect during ST_BANG is lcdBlank(), which is a single command byte. None of that shows up in this page.
  • The LEDs are on/off in both, but the board drives plain digital pins with no PWM, so neither can fade — the glow here is CSS, not brightness.
